# Prediction calibration on synthetic cohorts

Generated by `dart run tool/prediction/calibration_report.dart`. Every number below comes from data generated to a known distribution, so it describes how the engine behaves on those distributions — not how it behaves on people.

This is not a validation study, and no result here should be read as evidence that the uncertainty window is statistically calibrated for real users. The only real-cohort evaluation is elara-core's own walk-forward run on Utah/Creighton data (`test/backtest/REPORT.md`).

80 synthetic people per cohort, 36 cycles each, walk-forward with only recorded starts available at each step. "In window" is the share of starts that fell inside the ±windowDays the engine returned.

## What the cohorts show

- Error grows with irregularity, as it must: the same estimator cannot know the next draw of a wide distribution. A window that holds on regular cycles will not hold on irregular ones at the same rate.
- Gross misses are the number that matters for a user. They are reported separately because an average hides them.
- Short histories and mistyped dates both degrade the forecast, which is why the app distinguishes a recorded start from an estimate and why correcting a date refreshes the prediction.

## Limits of this report

1. The cohorts are synthetic. A synthetic "irregular" cycle is a uniform draw around a median; real irregularity has structure this cannot model.
2. It says nothing about whether the window is calibrated for any real user, and the app must not describe its intervals as validated.
3. The engine has not been changed on the basis of these numbers. They were checked before deciding whether a change was warranted, and the decision recorded in `docs/PREDICTION.md` was to leave the default model alone.
